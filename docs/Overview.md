Бот живет в докер-контейнере, подключается к хосту через docker.sock с рут-правами
```yaml
bot:
...

user: "0:0"
volumes:
  - /:/mnt/host
  - /var/run/docker.sock:/var/run/docker.sock
```

# Функционал:
### 1. Просмотр состояния сервера (`/health`):
	-  Состояние RAM (занято, абсолют/процент | всего | свободно, абсолют/процент)
	-  Состояние CPU (количество ядер, нагрузка в процентах)
	-  Состояние диска (занято, абсолют/процент | всего | свободно, абсолют/процент)
	-  Аптайм, дата и время последней перезагрузки:
		1. Uptime: Days, Hours:Minutes:Seconds,
		2. Rebooted: `DD:MM:YYYY, HH:MM (UTC +3)`
	-  Топ-6 процессов, потребляющих память:
			формат: `<место>`. `<название процесса>` - `<потребление абсолют (MB/GB)>` | `<потребление процент>`
	-  Топ процессов, нагружающих CPU:
			формат: <место>. <название процесса> - <потребление процент>
			
### 2. Мониторинг бэкапов (`/backups`):
	-  Поиск бэкапов по маске .dump
	-  Парсинг названия файла использованием regex для получения даты и времени создания (`db_name`, `datetime`)
	-  Раздельный подсчет количества бэкапов с одинаковым префиксом в названии (webui_db, litellm_db):
			`webui_db` - n штук, `litellm_db` - m штук. При m != n - warning в чат
	-  Подсчет общего размера (MB) дампов для каждой БД (`db_size * n`)
	-  Вывод собранной статистики в бот:
		-  Последние бэкапы:
			<`DD:MM:YYYY`, `HH:MM` из `datetime` файла> - <`db_name`>
		-  Размер последних бэкапов:
			<`db_name`>: <`db_size`>
		-  Всего бэкапов:
			<`db_name`>: `n`
		-  Общий размер бэкапов:
			<`db_name`>: <`db_size`> * `n`
	
### 3. Мониторинг Docker-контейнеров (`/docker_ps` и обработка триггеров):
	-  Общая сводка по всем контейнерам (`/docker_ps`):
			формат: `<название контейнера>` - `<статус (Up, Exited, Restarting)>` | `<время работы/остановки>`
	-  Отчет о падении контейнера (отдельное сообщение на каждый контейнер):
		-  Проверка кода остановки (Штатно, OOM, Ошибка контейнера)
		-  Штатная остановка (Exit 0): в сообщении указывается "Остановлен штатно"
		-  При нехватке памяти (OOM):
			-  Статистика по памяти перед падением (из системных логов)
			-  Последние логи контейнера для выявления причины
		-  При ошибке самого контейнера (Exit != 0):
			-  Последние 20 строк лога (трейсбек)
	-  Отчет о запуске/создании контейнера:
		-  Сообщение об успешном старте
		-  Последние 50 строк лога для визуального контроля успешной инициализации
	-  Алерты по ошибкам в логах:
		-  Отлов сообщений с уровнем `error` / `exception`
		-  Вывод фрагмента лога с текстом ошибки
		-  Троттлинг (лимит на частоту отправки), чтобы не заспамить чат при циклической ошибке
